## Findings and changes

1. The legacy Places route accepted a forgeable UI cookie without verifying its editor credential. The server now verifies the existing HMAC editor token, bounds request bodies/input, enforces same-origin browser requests and a per-process request budget, limits provider time/redirect behavior, prevents response caching, and suppresses provider diagnostic details. Both legacy clients send their existing editor token. Mocked-provider tests reproduce the original failure and verify the fix. No real paid provider was called; distributed quotas and hosted integration remain unverified.
2. Shared platform JSON parsing buffered a complete streamed request before enforcing 16 KB. It now cancels the stream at that limit. The regression tests preserve the original failing assertion and passing fix.
3. Existing SQL unit fixtures predated required MFA, new foreign keys and the final active Super Admin safeguard. Positive SQL role fixtures now carry the required simulated assurance; trusted workflow fixtures carry actor context; lifecycle fixtures retain an independent owner. Two legacy deleted-parent fixtures temporarily disable only the deletion guard inside a rollback transaction to construct their historical state. Bootstrap fixture reset uses transaction-local truncation with rollback. These tests do not represent genuine Auth; separate connected tests do. No runtime authorization was weakened and no applied migration changed.

Original failures remain in `evidence/b13-review/*before*`, `*first-attempt*` and `database-fixture-update-*`. The first HTTP harness lacked valid bodies/request keys and stopped at validation; the final harness uses valid shapes and checks actual 401/403/404 authorization outcomes. The initial GraphQL non-disclosure assertion was too weak: fresh valid requests establish that pg_graphql is disabled. That is unavailable-surface evidence, **not GraphQL tenant isolation acceptance**.
