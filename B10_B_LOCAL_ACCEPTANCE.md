# B10-B organization deletion window — local acceptance

September 18, 2026. Implements the explicit B10-B dispatch following B10-A `09e7553`. The bounded request/read-only/cancellation workflow is locally complete. Operational deletion/purge is not complete or implemented.

## Implemented behavior

- An active Organization Super Admin with current administration permission can request deletion after recent genuine TOTP, a named-organization confirmation and a version check. Database time sets a 30-day cancellation deadline. `organizations.deleted_at` stays null. A private lifecycle record, actor-bound exact receipt, audit event and one notification intent per organization Super Admin commit atomically.
- Any active same-organization Super Admin may cancel strictly before the deadline, including a different Super Admin with an independent ordinary `permissions` restriction. This is the expressly approved cancellation exception. It does not remove that restriction, reinstate suspended members, change roles, recreate invalidated invitations or modify schedules/history. Recent TOTP and current session/owner authority still apply.
- Organization policy locking precedes lifecycle authority/version/clock checks. Exact retries return the original recorded operation after current authorization and cannot extend the window. Changed/stale requests conflict. The deadline is checked after lock waits using database wall-clock time.
- At/past the deadline, state derives as `awaiting_purge`, preserving the same frozen access boundary. No timer, worker, physical deletion, soft deletion, billing call or hidden ordinary cancellation override was added. Direct organization deletion-field changes and organization DELETE are blocked by the workflow guard.
- Existing authorized read/history/export remain available. Independent export restrictions and suspended-member denials remain effective. Ordinary writes pause through shared guarded tables and early write-RPC checks. Coverage includes schedules/history, hierarchy, cross-organization copy/transfer, related imports, snapshot capture/retention/purge, templates/bindings, presentation, organization MFA policy, restrictions/roles, invitations/acceptance and ordinary membership changes. Account/session controls, lifecycle cancellation, audit and notification delivery are explicit exceptions; service-role table access is not a general bypass.
- The workspace displays a persistent read-only banner and eligible cancellation deadline/control. Same-actor drafts and pending requests stay mounted. Schedule editing and automatic snapshots pause; snapshot history does not invoke retention while frozen. Cancellation refreshes permissions and saved document version before saving resumes, retaining the draft if the saved version differs. A separate read/export template review avoids requiring edit permission for authorized template-backed export.
- The existing local notification ledger now supports multiple recipients per lifecycle event while retaining membership notices. Super Admins receive request/cancellation intents. The adapter only sends `@example.test` recipients to the configured loopback Mailpit sink. Failures remain retryable independently of lifecycle state. A bounded pending-notice page exposes 25 oldest notices; retries reveal the next entries. Best-effort delivery after the operation covers returned notices for that event; a larger/older backlog may require explicit retries. No background sender or real mail integration is included.

Three forward migrations were applied to the preserved local stack: `20260918053816_organization_deletion_window.sql`, `20260918053949_organization_lifecycle_notifications.sql`, `20260918054337_lifecycle_read_export_checks.sql`. Applied history was not rewritten. The second refines the generic trigger's record-field access and adds lifecycle delivery; the third preserves export-only template review and recipient labels.

## Stop and remaining gates

The environment is the same unlinked `roseland-b08-20260917` local stack (API 56121, app 3435, Mailpit 56124). Private credentials and TOTP material stay in mode-600 temporary fixtures. Reproducers are `scripts/test-organization-lifecycle-runtime.ts`, `scripts/test-organization-lifecycle-deadline.ts`, `scripts/test-organization-lifecycle-notifications.ts` and `scripts/serve-organization-lifecycle-user-flows.ts`. The browser tab and owned services are stopped with volumes retained; see [cleanup.txt](./evidence/b10b-organization-deletion/cleanup.txt).

Freeze enforcement is immediate in the database; background UI observation follows the existing polling/focus pattern. Some existing management controls may remain visible until their capability refresh and receive a database denial. This result does not establish full hosted/browser parity. Notification intent is idempotent; send-success/ack-loss or a crashed delivery worker may duplicate external mail on retry, so exactly-once delivery is not claimed.

The operational purge item remains open: separately review dependency inventory, retention/backup rules, resumable deletion, failure/retry evidence and ownership before dispatching any purge worker. Permanent deletion, scheduler, billing, exceptional factor recovery, B11, hosted/real-data/account/mail changes, push/deploy, migration and reskin remain outside this completion. No next batch starts automatically.
