## Approved B08 decision 3 — activity-based sessions, Remember me and reset revocation

On September 17, 2026, the user approved a **rolling 60-minute inactivity timeout** and optional **Remember me for personal devices**, allowing sign-in to survive browser close/reopen. The user explicitly rejected the proposed 12-hour absolute timeout: continuously active users should not be forced to sign out solely because a fixed elapsed time has passed. There is **no fixed elapsed-time forced sign-out for continuously active users**. This supersedes the tab-only/no-Remember-me and 12-hour proposals.

Only genuine user activity may advance the inactivity deadline. Background polling, token refresh and automatic renewal must not count as activity, erase an expired idle deadline or restart it. Closing/reopening and refresh must preserve elapsed inactivity; after 60 inactive minutes, fresh sign-in is required even with Remember me. Verify feasible provider/application enforcement and report limitations; no untested guarantee is claimed. Continuous activity never bypasses authorization: explicit sign-out, password-reset revocation, membership/account denial and required recent step-up MFA for sensitive actions remain binding.

The user separately approved this password-reset policy: after a successful reset, **sign out/invalidate all existing sessions and require fresh sign-in with the new password plus any required MFA**. Implementation must prove provider and application admission behavior, including already-issued access tokens; refresh-token revocation alone is not evidence that those tokens are immediately rejected. Preserve the existing admitted-transaction boundary: work already admitted may finish. Report any limitation rather than promising unsupported immediate cancellation or silently weakening the approved policy.

Persistent authentication is separate from draft/journal persistence: Remember me neither promises restoration of every unsaved draft nor changes existing account-bound recovery-journal lifetimes. Preserve unsaved-work protections, same-account recovery and isolation from other accounts. These are planning approvals only, with no implementation or hosted change dispatched.
