# Client recipient refresh — bounded local design

September19, before implementation. Authorized by OVERNIGHT_PARITY_FIXES.md. Start df803b3; continuation /private/tmp/roseland-b15-overnight. Frozen3506 remains unchanged.

Exchange the original new-link fragment or verified legacy query token for an authenticated-encrypted HttpOnly cookie. Keep only a random128-bit non-secret recipient selector in the address. The cookie contains the original grant digest (not the original raw bearer), legacy binding if applicable, selector, issue time and fixed expiration. AES-256-GCM uses a purpose-separated key derived from the existing server-only service secret, with issuer origin and selector bound as additional authenticated data. This adds no browser-readable reusable secret, new external service, database table, role, grant or configuration secret.

Each selector has a narrowly scoped cookie Path at its own read endpoint. Parallel different shares cannot overwrite each other's cookie or silently choose the last-opened share. Cookies are HttpOnly, SameSite=Strict, host-only, Secure on HTTPS; loopback HTTP necessarily uses non-Secure cookies. The entire route remains gated to the existing explicit local configuration. Hosted HTTPS behavior is unverified and not enabled by this pass.

The existing read_schedule_client_view RPC remains the authority on EVERY exchange/read/print refresh. Its grant expiry, revocation, sponsor restrictions, account status, projection and rate budget remain unchanged. Cookie expiry is fixed at exchange (maximum30 days, or earlier verified legacy expiry), never slid on reads. The cookie can physically remain after the underlying grant's earlier expiry, but confers no access then: the original grant is rechecked and denial clears it. Thus effective recipient access never outlives or renews the original link; no cached authorization or document is trusted. This transport lifetime distinction is explicit, not a changed link-expiry contract.

Before showing the document or replacing its address with the selector, perform a cookie-authenticated read to prove the browser accepted the cookie. If cookies are blocked, show a contextual retry/original-link message; do not silently use localStorage, sessionStorage or a retained JavaScript bearer as persistence. Clear the original URL token promptly and keep it only in component memory until exchange/confirmation succeeds or the component is left. A valid retry may use that still-pending input. Invalid supplied input never falls back to a prior share's cookie.

Use same-origin POSTs with Origin/Sec-Fetch-Site checks, existing bounded JSON parsing and private/no-store/no-referrer headers. Do not log cookie bodies, bearer fragments, raw legacy tokens, grant digests or credential-bearing URLs in evidence. Route selectors are not shareable credentials; Copy Client link continues to produce the original authorized link.

Verification: actual valid reload; two different links/tabs; invalid selector/tampered/missing/cross-link cookie; wrong origin; explicit original token with old selector; original expiry/revocation/sponsor denial on subsequent reads; fixed cookie expiry; unavailable cookies; restricted projection; legacy binding. Tests of server denial use isolated fictional fixtures. No retained review membership is changed and no hosted feature is deployed.
