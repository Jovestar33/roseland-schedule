# B11 scoped sharing — local acceptance

September 18, 2026. Implements the explicitly authorized B11 checkpoint following `d161686`, before the isolated review preview and B12 synthetic reconciliation. Familiar interface and existing output paths retained; no branding or design implementation.

Authenticated Team links use stable organization/schedule IDs and ordinary sign-in/current authorization. Editors and above create Client links within current read/edit/export/share and inherited template-source restrictions. Leadership may restrict sharing using the existing Permissions interface. Creators, authorized Organizers and leadership revoke within effective scope. New 256-bit random bearers are stored only as SHA-256 digests, expire after exactly 30 database days, and use immutable actor-bound create request identity plus saved-version checks. Retries neither extend expiry nor revive revoked grants. Link lists paginate without exposing token material.

The server-only Client projection matches the legacy allowlist, including ordinary row notes and excluding contacts, call sheets, status, history and unknown fields. Each read rechecks the grant and its sponsor's current roles, restrictions, source bindings and account status. Reads serialize with policy changes and revocation; already admitted responses/copies cannot be recalled. Pending deletion preserves existing scoped read access while new link creation/revocation remains an ordinary frozen write. Two additional tenant tables use the common B10 write guard. No anonymous or authenticated direct resolver/table privilege is granted.

The local legacy bridge validates original name-bound HMAC and expiry, then resolves trusted imported aliases to stable IDs. Alias records are retained until separately approved retirement, at least the agreed 12-month route window; token expiry is never extended. Leadership/authorized creator can revoke the entire alias, invalidating all original links for it. No real legacy secrets, links or inventory were accessed; an actual migration must bind a reviewed sponsor and original secret/alias inventory. Bare names never authorize access. Original query-token formats inherently arrive in the request URL; the local page clears them and supplies no-referrer/no-store headers, but hosted request-log redaction still requires B15 verification. New links use fragments and clear them after capture.
