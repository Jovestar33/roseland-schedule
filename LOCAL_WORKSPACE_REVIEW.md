## Behavior and boundaries

The independent `ROSELAND_LOCAL_WORKSPACE=supabase` gate requires a loopback Host, matching server/browser loopback Supabase configuration, the existing server workflow opt-in and a server-only workflow credential. Netlify/Vercel environments and nonloopback destinations are rejected. Only the URL and anonymous key reach the client. The other standalone local routes and setup gate remain independently disabled. The workspace skips legacy shared-PIN routing and CMS initialization only on its own gated path.

One Supabase client owns password sign-in, MFA/session events and explicit sign-out. Credentials, tokens, schedule edits, modal drafts and invitation request state live only in memory; there is no local/session-storage persistence, refresh-token persistence, automatic background token refresh or URL-session detection. Fetches are pinned to the configured local origin, do not follow redirects, bypass caches and have bounded timeouts. Real Auth verification, existing MFA/recent-auth rules, Data API session admission and RLS remain authoritative.

Organization navigation resolves the current actor's exact active membership and undeleted organization. Owner/Admin roles expose invitation management; Member navigation does not. The directory is paginated. Schedule lists are explicitly organization-filtered under existing RLS. Existing `can_edit_production` decides whether the editor exposes editing controls or a read-only schedule view. Server RPCs still reject unauthorized writes. Acceptance uses the prior supplied-ID/own-receipt contract and offers **Open organization schedules**, which performs a new authorized scope lookup.

Internal navigation and browser back/forward retain mounted panels. One schedule/document/undo history is retained, with its organization-bound view hidden when another organization is selected. Opening a different schedule or reloading dirty work requires explicit discard; cancellation retains it. Invitation management has a separate retained panel for each visited organization, so an immutable review or pending result cannot become another organization's request. The acceptance panel retains its actor-bound invitation ID. The global unfinished-work indicator includes open schedule modal drafts, not just changes already applied to the document.

Account generations and independent request tickets reject stale directory/navigation responses. Schedule list results additionally match their requested organization; permission results match the record, token and organization. A changed token invalidates outstanding directory/navigation tickets. Shared REST 401 handling ignores a response tied to an older token. Changed accounts and explicit sign-out invalidate controllers, clear every panel and reset document/undo state. Sign-out/account switching is disabled while a panel request is in flight; unfinished work requires a concrete clear confirmation. A missing/expired/revoked session retains the same actor's memory for explicit reauthentication. An already admitted request may still finish, as documented in the existing admission contract.

Modal portals now respect an optional visibility context, defaulting to the original visible behavior everywhere else. The workspace hides portals outside the active authorized editable panel without unmounting their form state. This prevents a contact/notes/status dialog or its keyboard handler from remaining over a different screen. Returning restores the retained draft; opening a different document still requires discard. Closing a modal explicitly retains its existing cancellation semantics. None of this grants offline authorization or erases data already legitimately read from a browser's memory.

Full page reload, closing the tab or navigating out of this in-memory workspace loses local drafts. Dirty work registers a before-unload warning. The workspace does not add delivery, signup, password/MFA recovery, invitation discovery/preview, organization provisioning UI, membership administration, schedule lifecycle menus, related-store projections or complete editor/library parity. It is a bounded local integration, not production onboarding or a security/parity sign-off.
